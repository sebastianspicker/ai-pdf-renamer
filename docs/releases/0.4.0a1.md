# Folionym 0.4.0a1

This alpha candidate provides supervised PDF naming through a CLI, a Textual
terminal interface, and a local browser interface. It is not evidence that a
GitHub prerelease has been published.

## Installation from GitHub assets

If the prerelease is published, download its wheel, source distribution, and
`SHA256SUMS` into one directory. Verify the artifacts, then install the wheel:

```bash
shasum -a 256 -c SHA256SUMS
python3.14 -m pip install \
  './folionym-0.4.0a1-py3-none-any.whl[pdf,tui,web]'
```

This version is not documented as a package-index release.

## Included interfaces

- `folionym` for batch, single-file, manual, and watch operation
- `folionym-tui` for terminal configuration, Preview, and Apply
- `folionym-web` for the loopback Source, Preview, and exact Apply workflow
- `folionym-undo` for compatible same-directory rename logs

Optional extras add OCR, token-aware limits, the TUI, and the browser service.
OCR also requires OCRmyPDF's platform prerequisites. Vision requires a
compatible model at the configured HTTP endpoint.

## Limitations

- CPython 3.14 or later is required. Release verification uses 3.14.6.
- Run one process per target directory.
- Keep backups and review names before applying them.
- The application does not sandbox PDF or OCR processing.
- There is no hard input byte limit, default page extraction is unlimited,
  worker count has no hard maximum, and OCR has no application-level timeout.
- TUI Preview and Apply are independent runs. Apply to folder and Rename one
  PDF require confirmation with Cancel first.
- Browser plans and reports last only for the current server process.
- Remote LLM endpoints and hooks can receive document-derived content or
  metadata. Use HTTPS and review the [security policy](../../SECURITY.md).

For installation from source, configuration, and usage, see the
[README](../../README.md). Maintainers should use the procedure in
